    6. Client-side JavaScript validation

    In the previous chapter, we looked at server-side validation. Let’s return to the architecture of a Spring MVC application:

    DB

    So far, the pages sent to the client did not contain any JavaScript. We will now explore this technology, which will initially allow us to perform client-side validation. The principle is as follows:

    • JavaScript posts the values to the web server;
    • and so before this POST, it can check the validity of the data and prevent the POST if the data is invalid;

    We will use the form that we validated on the server side. We will now offer the option to validate it both on the client side and on the server side.

    Note: This is a complex topic. Readers not interested in this subject can skip directly to paragraph 7.

package istia.st.springmvc.validators;

import istia.st.springmvc.models.Form01;

import org.springframework.validation.Errors;
import org.springframework.validation.Validator;

public class Form01Validator implements Validator {

    // validation range
    private double min;
    private double max;

    // constructor
    public Form01Validator(double min, double max) {
        this.min = min;
        this.max = max;
    }

    @Override
    public boolean supports(Class<?> class) {
        return Form01.class.equals(class);
    }

    @Override
    public void validate(Object form, Errors errors) {
        // Validated object
        Form01 form01 = (Form01) form;
        // the value of [double1]
        Double double1 = form01.getDouble1();
        if (double1 == null) {
            return;
        }
        // the value of [double2]
        Double double2 = form01.getDouble2();
        if (double2 == null) {
            return;
        }
        // [double1+double2]
        double sum = double1 + double2;
        // validation
        if (sum < min || sum > max) {
            errors.rejectValue("double2", "form01.double2", new Double[] { min, max }, null);
        }
    }

}

    As mentioned above, there is an issue with generating the attribute [data-val-required="This field is required"]. We have encountered predefined attributes [th:text, th:value, th:class, ...] but there is no [th:data-val-required] attribute.

        }
        return false;
    }
    // validity check
    var min = Globalize.parseFloat(param.min);
    var max = Globalize.parseFloat(param.max);
    var sum = value1 + value2;
    var valid = sum >= min && sum <= max;
    // logs
    if (logs.custom3) {
        console.log(jSON.stringify({
            "[custom3] valid" : valid
        }))
    }
    // result
    return valid;
});

$.validator.unobtrusive.adapters.add("custom3", [ "field", "max", "min" ], function(options) {
    options.rules["custom3"] = options.params;
    options.messages["custom3"] = options.message.replace("''", "'");
});

    6.3.21. Enabling/Disabling Client-Side Validation

    As long as client-side validation is enabled, server-side validation is never seen because posted values only reach the server if they have been validated on the client side. To see server-side validation in action, you must disable client-side validation. The [vue-01.xml] view provides two links to manage this enablement/disablement:

    
<a id="clientValidationTrue" href="javascript:setClientValidation(true)">
    <span style="margin-left:30px" th:text="#{client.validation.true}"></span>
</a>

    <span style="margin-left:30px" th:text="#{client.validation.false}"></span>
</a>

    What is the purpose of this [setClientValidation2] function? It is used to manage POST requests. Since the [clientValidation] field is a hidden field, it is posted and returned with the form sent back by the server. We then use its value to restore client-side validation to the state it was in before the POST. This is because there is no JavaScript state preserved between requests. The server must therefore pass the information needed to initialize the new view’s JavaScript to that view. This is usually done in the [$(document).ready] function.

    Let’s return to the [setClientValidation] function, which handles clicks on the links to enable/disable client-side validation:

    
// client-side validation
function setClientValidation(activate) {
    // we handle the activation/deactivation of client-side validation
    setClientValidation2(activate);
    // store the user's choice in the hidden field
    clientValidation.val(activate ? "true" : "false");
    // additional adjustments
    if (activate) {
        // client-side validation is enabled
        // clear all server error messages
        clearServerErrors();
        // validate the form
        form.validate().form();
    } else {
        // client-side validation is disabled
        // clear all client-side error messages
        clearClientErrors();
    }
}

// clear client errors
